PBX Virtual¶

Los clientes de PBX Virtual están diseñados para proporcionar servicio a clientes con múltiples terminales que requieren flujos de llamadas con muchas características.

Consejo

Algunos campos descritos a continuación pueden no ser visibles dependiendo de las funcionalidades habilitadas.

Nombre

Establece el nombre para este cliente.

Dominio SIP

DNS para este cliente. Ver sección Dominio SIP del Cliente.

Características

Permite la configuración de características disponibles para este cliente. Las secciones relacionadas se ocultan en consecuencia y el cliente no puede usarlas.

Método de facturación

Cuando la función de facturación está habilitada, determina cuándo se valorarán las llamadas. ‘ninguno’ desactiva la facturación. Ver sección Tarificación.

Corporación

Seleccione a qué corporación pertenece este cliente. Permite usar Amigos Inter VPBX para marcar otras extensiones de clientes.

Configuración Geográfica

Configuración general del cliente para idioma y zonas horarias. La mayoría de las configuraciones en la sección se pueden configurar por usuario si es necesario.

Moneda

La moneda elegida se usará en el cálculo de precios, facturas, movimientos de saldo y operaciones de dinero restante de este cliente.

Máximo de llamadas

Limita tanto las llamadas externas entrantes como salientes (0 para ilimitado).

Filtrar por dirección IP

Si se establece, la plataforma solo permitirá llamadas provenientes de IP/rangos o países permitidos.

Países permitidos por GeoIP

Si Filtrar por dirección IP está habilitado, se permitirá el tráfico de los países seleccionados.

Uso máximo diario

Limita las llamadas externas salientes cuando se alcanza este límite dentro de un día. A medianoche se restablecen los contadores y se reactivan las cuentas.

Correo electrónico

Se enviará un correo electrónico de notificación a la dirección dada cuando se alcance el uso máximo diario configurado. Dejar vacío para evitar la notificación.

Datos de la factura

Datos incluidos en las facturas creadas por esta marca. Esta sección también permite mostrar/ocultar detalles de facturación en el portal del cliente, como Facturas, Perfiles de Tarifas y Precio de llamadas externas.

Notificaciones

Configurar las Plantillas de Notificación por correo electrónico para usar con este cliente.

DDI saliente

Selecciona un DDI para las llamadas salientes de este cliente, si no se anula en un nivel inferior.

Conjunto de retransmisión de medios

Como se mencionó anteriormente, la retransmisión de medios se puede agrupar en conjuntos para reservar capacidades o con un propósito geográfico. Esta sección te permite asignarlos a los clientes.

Método de Distribución

‘Basado en hash’ distribuye las llamadas haciendo hash de un parámetro que es único por cliente, ‘Round robin’ distribuye las llamadas equitativamente entre los AS y ‘estático’ se usa para fines de depuración.

Servidor de Aplicaciones

Si se usa el método de distribución ‘estático’, selecciona un servidor de aplicaciones aquí.

Grabación de llamadas bajo demanda

Se muestra solo si la función Grabación está habilitada para el cliente, permite habilitar y deshabilitar la grabación de llamadas bajo demanda. Si está habilitado, puedes elegir cómo invocar y el código de servicio si es necesario.

Permitir al Cliente eliminar grabaciones

Se muestra solo si la función Grabación está habilitada para el cliente, muestra/oculta el botón de eliminación de grabaciones en la sección Grabaciones de Llamadas del cliente.

La mayoría de las características son autoexplicativas, pero notificación de voz merece una explicación: si las habilitas, cuando una llamada falla, el usuario escuchará una locución explicando lo ocurrido (“no tienes permisos para realizar esta llamada”, “la llamada no se puede facturar”, etc.)

Tanto Método de Distribución como Servidor de Aplicaciones son visibles solo para el Administrador Principal.

Advertencia

El método de distribución ‘Round-robin’ está reservado para clientes grandes cuyas llamadas no pueden ser manejadas en un solo AS. Usa ‘Basado en hash’ para los restantes, ya que ‘Round-robin’ impone algunas limitaciones a las características del cliente (sin colas, sin conferencias).

Subsecciones adicionales¶

Cada entrada en esta tabla tiene estas opciones adicionales:

  • Lista de fuentes autorizadas: si Filtrar por dirección IP está habilitado, esta subsección permite agregar direcciones o rangos de red.

Error

No se permitirá ninguna llamada saliente si Filtrar por dirección IP está habilitado y la lista correspondiente está vacía.

  • Lista de administradores de clientes: esta subsección permite gestionar las credenciales del portal para este cliente específico. Lea ACLs para una mayor explicación sobre administradores de clientes restringidos.

  • Lista de perfiles de tarifas: esta subsección permite gestionar los perfiles de tarifas que se utilizarán para facturar sus llamadas salientes.

Advertencia

No se permitirá ninguna llamada saliente para este cliente a menos que haya un perfil de tarifas activo que pueda facturar la llamada específica.

Importación masiva de usuarios¶

La acción Importar usuarios de cada fila de PBX Virtual crea o actualiza sus usuarios a partir de un fichero CSV, junto con sus terminales, extensiones y DDIs de salida. El diálogo muestra el formato esperado, ofrece una plantilla descargable e informa del resultado de cada línea. Solo se muestra a los administradores con permiso para importar usuarios.

La misma operación está disponible a través de la API de marca, consulte Uso de la API.

Formato del CSV¶

Un usuario por fila y once columnas, en este orden (los campos marcados con * son obligatorios):

Nombre*

Nombre del usuario. Junto con los apellidos identifica al usuario dentro del cliente: una fila con un nombre y apellidos existentes actualiza ese usuario.

Apellidos*

Apellidos del usuario.

Correo electrónico

Email del usuario. Debe ser único en toda la plataforma, por lo que una dirección que pertenezca a un usuario de otro cliente hace fallar la fila. Cuando ningún usuario del cliente tiene el nombre y apellidos indicados, la fila actualiza al usuario del cliente que posee ese email.

Nombre del terminal

Nombre del terminal (letras, dígitos, _ y *). Se crea si no existe y se asigna al usuario.

Contraseña del terminal

Contraseña SIP del terminal: al menos 10 caracteres con 3 mayúsculas, 3 minúsculas, 3 dígitos y uno de + * _ -. Déjela vacía para conservar la contraseña actual de un terminal existente o para generar una aleatoria en un terminal nuevo.

Modelo del terminal

Identificador de un modelo de terminal existente, tal como aparece en Modelos de terminal (por ejemplo YealinkT21P_E2).

MAC

Dirección MAC del terminal, 12 caracteres hexadecimales sin separadores.

Extensión

Número de extensión asignado al usuario. Se crea si no existe.

País del DDI

Código ISO del país del DDI (por ejemplo ES). Si está vacío se usa el país del cliente.

Número del DDI

Número del DDI de salida, solo dígitos y sin prefijo de país. Se crea y se enruta al usuario si no existe.

Proveedor del DDI

Nombre de un proveedor de DDI de la marca.

Las columnas pueden separarse con comas o con puntos y coma, y el fichero puede estar codificado en UTF-8, con o sin BOM, o en Windows-1252. Las filas vacías se ignoran y una primera fila con los nombres de las columnas (name,lastname,email,...) se omite, de modo que la plantilla puede rellenarse directamente.

Ejemplo de fichero CSV

Alice,Allison,alice@example.com,alice_t21,Zx9*abc123DEF,YealinkT21P_E2,001565aabbcc,301,ES,944000301,
Bob,Bobson,bob@example.com,bob_t21,,YealinkT21P_E2,,302,,,
Carol,Smith,carol@example.com,,,,,,,,

La primera fila crea el usuario con su terminal, extensión y DDI de salida. La segunda deja que la plataforma genere la contraseña del terminal y no crea DDI. La tercera crea un usuario sin terminal ni extensión.

Reimportar un fichero¶

Las filas se comparan con los usuarios existentes del cliente por nombre y apellidos, o por email cuando ninguno tiene ese nombre y apellidos, de modo que el mismo fichero puede importarse de nuevo:

  • Importar el mismo fichero dos veces no cambia nada ni crea duplicados.

  • Cambiar un valor e importar de nuevo actualiza solo ese valor.

  • Cambiar el nombre o los apellidos de un usuario manteniendo su email renombra a ese usuario.

  • Las columnas vacías de un usuario existente no se tocan: nunca eliminan su terminal, extensión, DDI o email.

  • Los terminales se identifican por nombre, o por MAC cuando el nombre es nuevo, de modo que un terminal puede renombrarse conservando su MAC.

  • Un DDI existente del cliente puede ser el DDI de salida de varios usuarios; su enrutamiento entrante no se modifica.

Los usuarios nuevos se crean inactivos: pueden usar su terminal, pero no pueden entrar en el portal de usuario hasta que un administrador les asigne una contraseña.

Errores¶

Las filas válidas se importan y el resto se informan con su número de línea y el motivo. Corrija las líneas indicadas e importe el fichero de nuevo; las filas ya importadas simplemente se actualizan.

Una fila falla, entre otros motivos, cuando:

  • su nombre o apellidos están vacíos, o un valor tiene un formato no válido;

  • su email pertenece a un usuario de otro cliente, o a otro usuario cuando la fila ya coincide con un usuario por nombre y apellidos; su terminal o extensión ya pertenece a otro usuario, su MAC pertenece a otro terminal, su extensión está enrutada a una cola o a cualquier otro elemento, o su DDI pertenece a otro cliente o a otra marca;

  • su modelo de terminal, país o proveedor de DDI no existe.

Algunos errores afectan a todo el fichero y no se importa nada: un fichero vacío, una fila con un número de columnas incorrecto o el mismo usuario, email, terminal, MAC, extensión o DDI repetido en varias filas. Se informan como línea 0.

Si la importación se detiene por un error inesperado, las filas restantes se informan como no procesadas: importe el fichero de nuevo cuando el problema esté resuelto.

Guardar el fichero desde Excel¶

Use Guardar como y elija CSV UTF-8 (delimitado por comas); el formato CSV (delimitado por comas) también funciona. Según la configuración regional, Excel separa las columnas con punto y coma, que también se acepta. Mantenga las columnas de MAC, extensión y DDI como texto; de lo contrario Excel puede eliminar los ceros iniciales o reescribir los números largos en notación científica.

Uso de la API¶

La importación se expone como POST /users/mass_import en la API de marca. Espera una petición multipart/form-data con el identificador company y el fichero csv:

curl -X POST https://brand.example.com/api/brand/users/mass_import \
    -H "Authorization: Bearer ${TOKEN}" \
    -F company=1 \
    -F csv=@users.csv

La respuesta resume la importación y enumera cada línea fallida:

{
    "created": 2,
    "updated": 0,
    "errors": [
        {
            "line": 2,
            "message": "Email bob@example.com belongs to a user of another client"
        }
    ]
}

Exportación masiva de usuarios¶

La acción Exportar usuarios de cada fila de PBX virtual descarga un fichero CSV con los usuarios del cliente en el formato de la Importación masiva de usuarios, para poder editarlo en una hoja de cálculo e importarlo de nuevo en la misma PBX virtual, o usarlo para dar de alta los usuarios en otra. Solo se muestra a los administradores que pueden ver la importación de usuarios.

La misma operación está disponible a través de la API de marca, ver Uso de la API.

Qué se exporta¶

Una fila por usuario del cliente, ordenadas por nombre y apellidos, con las once columnas de la importación y una primera fila con sus nombres. Las columnas de terminal describen el terminal asignado al usuario y la columna de extensión su extensión. Las columnas de DDI solo se rellenan cuando el usuario tiene su propio DDI de salida: los usuarios que llaman con el DDI por defecto del cliente las tienen vacías.

La columna de contraseña de terminal siempre va vacía: las contraseñas SIP nunca se escriben en un fichero que puede circular. Al importar el fichero se conserva la contraseña actual de los terminales existentes y se genera una aleatoria para los nuevos.

El fichero no es una copia del cliente, solo contiene lo que admite la importación. No incluye:

  • la configuración de los usuarios: permisos de acceso, idioma, buzón de voz, contraseña del portal, etc.;

  • lo que no pertenece a un usuario: IVRs, grupos de salto, colas, extensiones enrutadas a otros elementos y terminales sin usuario;

  • otros DDIs distintos del DDI de salida de cada usuario, ni sus rutas de entrada.

Formato del fichero¶

Las columnas se separan con punto y coma y el fichero se codifica en UTF-8 con BOM, de modo que Excel lo abre correctamente con un doble clic y la importación lo admite tal cual. Los valores con separadores o comillas van entrecomillados, y los valores que empiezan por =, +, - o @ llevan delante una comilla simple para que las hojas de cálculo no los ejecuten como fórmulas; la importación elimina esa comilla.

La exportación se rechaza cuando dos usuarios del cliente comparten nombre y apellidos, porque la importación no podría distinguirlos: renombre uno de ellos y exporte de nuevo.

Importar en otra PBX virtual¶

El fichero puede dar de alta los usuarios de otra PBX virtual, en esta plataforma o en otra distinta, con estas limitaciones:

  • Los emails son únicos en toda la plataforma: mientras el cliente de origen conserve sus usuarios, las filas con sus emails fallan. Vacíe o cambie la columna de email.

  • Una MAC o un DDI no pueden pertenecer a dos clientes: las filas con la MAC de un terminal o el DDI que siguen asignados al cliente de origen fallan. Libérelos en el cliente de origen o vacíe esas columnas.

  • Los modelos de terminal se buscan por identificador y los proveedores de DDI por nombre dentro de la marca, así que deben existir en el destino con los mismos valores.

  • Los terminales reciben una contraseña aleatoria nueva, ya que las contraseñas no se exportan.

  • Los usuarios nuevos se crean inactivos, como cualquier usuario importado.

Uso de la API¶

La exportación se expone como GET /users/mass_export en la API de marca, con el identificador company como parámetro de consulta. La respuesta es el fichero CSV:

curl -o DemoCompany-users.csv \
    -H "Authorization: Bearer ${TOKEN}" \
    "https://brand.example.com/api/brand/users/mass_export?company=1"
